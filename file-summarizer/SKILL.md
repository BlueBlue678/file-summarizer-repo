# File Summarizer（文件重点总结）

## Overview

提供一套统一流程，把任意格式的文件或冗长文本转化为精炼、结构化的摘要。通过"提炼重点 + 简化描述"两步法，保留读者真正需要的信息，去除冗余表述，并按一致的输出模板呈现。

核心价值在于**方法论与编排**，而非重复实现文件解析——读取环节复用 WorkBuddy 已有的专用能力（PDF、表格、PPT、Word 等 skill）。

## Core Principles（核心原则）

动手前先区分两个目标：

- **提炼重点**：从内容中筛选出对读者最有价值的信息——结论、决策、数据、行动项、风险点，而不是逐段翻译。
- **简化描述**：把冗长、嵌套、术语堆砌的句子改写成简短直白的话，保持原意不变，绝不改动关键数据。

判断标准：一个忙碌的人只读摘要，能否在 30 秒内抓住文件要害？

## Workflow（工作流程）

### Step 1: 识别内容来源与类型

确定待总结的内容属于哪一类：本地文件、在线内容、直接粘贴的文本、或多文件集合。记录文件类型（扩展名）与体量（页数/字数），据此决定后续处理深度。

### Step 2: 选择读取方式

按类型复用合适的工具，不要自己从零解析二进制格式。查阅 `references/format-routing.md` 获取完整路由表。

快速路由：
- PDF → workbuddy-pdf skill
- 表格 xls/xlsx/csv → workbuddy-sheetagent skill
- PPT → workbuddy-pptx skill
- Word doc/docx/wps → workbuddy-office-routing 路由
- 图片（含文字）→ 视觉识别 / OCR
- 网页 URL → WebFetch
- 文本 / Markdown / JSON / 代码 → 直接 Read
- 在线文档（腾讯文档等）→ 对应文档 skill

同一任务涉及多种格式时，逐类分别读取后统一进入 Step 3。

### Step 3: 提取与清洗内容

- 读取原文，保留结构线索（标题、章节、表格、列表）。
- 去除与主题无关的噪音：页眉页脚、广告、重复段落、格式标记。
- 超长内容先分块或按章节提取，避免上下文溢出（见 Special Cases）。
- 扫描件/图片先 OCR 转文字，再进入下一步。

### Step 4: 提炼重点

应用"四要素筛选法"逐段判断并保留：

1. **结论/观点**：作者最终想表达什么。
2. **关键数据**：数字、日期、金额、百分比、指标。
3. **决策与行动项**：已定的决定、待办、责任人、时间节点。
4. **风险与问题**：明确指出的问题、限制、待解决事项。

丢弃：背景铺陈、重复论证、纯修辞、无关示例细节（除非示例本身是关键证据）。

详细方法与各类型文件的重点清单见 `references/summary-frameworks.md`。

### Step 5: 简化描述

对保留下来的每条信息执行改写：

- 把长句拆成短句，一句一个意思。
- 删除冗余限定词、套话和重复表达。
- 把术语/缩写替换为通俗说法（首次出现可保留原词并加注）。
- 使用主动语态和具体动词，避免"进行了……的处理"式空话。
- 保留所有关键数据与专有名词，绝不因简化而丢失数字或改变结论。
- 每条要点控制在 1–2 行。

### Step 6: 结构化输出

按标准模板组织摘要，并根据用户需求选择详略级别。完整模板与示例见 `references/summary-frameworks.md`。

标准输出模板：

```
## 一句话概括
<用一句话说明这份文件是什么、核心结论是什么>

## 关键要点
- 要点一（1–2 行）
- 要点二
- 要点三

## 重要数据
- 数据/指标 1
- 数据/指标 2

## 行动项与风险（如有）
- 待办 / 风险点
```

详略级别：
- **极简**：仅"一句话概括" + 3–5 条要点。
- **标准**：完整模板（默认）。
- **详细**：标准模板 + 分章节展开 + 关键原文引用。

## Multi-File（多文件与批量处理）

- 对每个文件分别生成摘要，再在末尾给出"整体概览"（跨文件的共同主题与差异）。
- 保持输出格式一致，便于横向对比。
- 明确标注每条摘要对应的文件名。

## Special Cases（特殊场景）

- **超长文件**：按章节/分块提取，每块独立提炼后合并去重；优先保证结论与数据完整。
- **扫描件/图片**：先 OCR；质量差时提示用户，并标注不确定内容。
- **无文本层或加密 PDF**：尝试 OCR，或请求用户提供可复制文本。
- **含图表**：用文字描述图表的核心趋势与数值，不依赖用户看图。
- **原文不清晰或前后矛盾**：在摘要中标注"[原文存疑]"，不擅自补全。

## Quality Check（质量检查）

输出前逐项确认：

- 一句话概括是否准确反映核心结论？
- 关键数据是否与原文一致（数字、单位、时间）？
- 每条要点是否简短（1–2 行）且无重复？
- 是否遗漏行动项或风险点？
- 简化后是否仍保持原意？
